# trip-planner: 사실은 한 번만 적고, 결과물은 넷

여행 계획이 틀어지는 건 대개 같은 사실이 여러 곳에 적혀 서로 어긋나서다. 포스터에는 09:00 도착, 지도에는 귀국이 두 번, 웹앱에는 집결이 14:30 과 15:00. 그래서 이 스킬은 **모든 사실을 데이터 파일 하나에 딱 한 번** 적고, 결과물 넷은 전부 거기서 만든다. 결과물을 손으로 고치지 않는다. 고칠 게 생기면 데이터 파일을 고치고 다시 만든다.

```
여행.yaml (사실은 여기에 한 번만)
   ├─ J 검사기 → 틀린 곳 목록 (만들기 전에)
   ├─ ① 인포그래픽 PNG (폰 1080x1920, A4)
   ├─ ② 웹앱 HTML 한 파일 (오프라인)
   ├─ ③ 지도 KML (구글 내 지도 > 가져오기)
   └─ ④ 시트 xlsx (드라이브에 올리면 구글 시트)
```

## 필요한 것

- Python 3.10+, `pip install pyyaml openpyxl playwright` 그리고 `playwright install chromium` (인포그래픽 PNG 용)
- 쓰는 바깥 서비스: 지도 조각 OpenStreetMap(키 없음, 가벼운 개인 사용만), 사진 위키미디어 공용(키 없음, 해외),
  한국관광공사 관광사진 API(국내, 공공데이터포털 키를 환경변수 `DATA_GO_KR_KEY` 에). 구글 드라이브와 내 지도에 올리는 건 사람이 한다.
- 결과물 넷 말고 **한 장 그림(가로 포스터, `build_poster.py`)과 인스타 넘김(1080×1350, `build_carousel.py`)**도 같은 데이터에서 만든다.

스크립트 위치: 이 SKILL.md 옆 `scripts/`. 아래 `<스킬>` 은 이 폴더의 절대경로.

## 절차

> **완성본 먼저.** 처음부터 넷을 같이 만들지 않는다. 한 장 그림(인포그래픽) 하나를 본보기 수준으로 먼저 완성하고, 사용자 OK 를 받는다. 그다음 그 색·글꼴·짜임을 웹앱·시트·지도에 옮긴다. 디자인을 고칠 때도 같다. 한 장 그림부터 고치고, 넷을 한꺼번에 고치지 않는다.

### 1. 묻기 (모자란 것만)

사용자가 준 메모, 시트, 지도에서 먼저 뽑고, 없는 것만 번호로 묻는다.
- 어디, 언제(시작일, 끝나는 날), 누구(인원과 나이, 아이나 어르신, 못 먹는 것)
- 도착: 날짜, 시각, 공항. **하나만.** 귀국: 출발 시각, 공항에 몇 시까지. **하나만.** 두 안이 있으면 지금 정하게 한다.
- 꼭 갈 곳, 이미 한 예약(시간 지정 입장권은 시각까지)
- 그 나라 공휴일 (날짜가 겹치면 휴무가 바뀐다)

사람 이름은 데이터에 넣지 않는다. "어른 1", "아이 1" 처럼 적는다.

### 2. 데이터 파일 쓰기

`<스킬>/examples/tokyo-family.yaml` 을 본보기로 새 파일을 쓴다. 칸 설명은 `references/schema.md`.

- 장소마다 좌표(lat, lon), 영업시간(hours), 휴무 요일(closed), 공휴일이면 다음 날 쉬는지(holiday_shift), 나이 제한(min_age), 예약(reservation), **확인한 날짜(checked)** 와 출처(source).
- 영업시간과 휴무는 지어내지 않는다. 확인할 수 없으면 비워 두면 검사기가 "확인 필요"로 알려 준다. 웹에서 확인했으면 source 에 주소, checked 에 오늘 날짜.
- 일정 항목은 시각(time), 머무는 분(stay), 장소(place), 할 일(what), 주의(note), 다른 안(alt: 비, 휴무, 지연), 오는 길(go: mode, minutes). 이동 시간이 들쭉날쭉하면 minutes 에 여러 안을 적는다(예: 공항 버스 [60, 75, 90]). 추정이면 `estimated: true`.
- 메모(note) 안에 시각을 또 적지 않는다. 적으면 검사기가 칸과 비교해 다르면 잡는다.

### 3. J 검사

```
python <스킬>/scripts/check_trip.py <여행.yaml>
```

`오류` 는 고친 뒤에만 다음으로 간다. `경고` 는 사용자에게 보여 주고 정하게 한다. 무엇을 잡는지는 `references/rules.md`.

고치는 법은 데이터를 바꾸는 것이다: 시각을 옮기거나, 다른 날로 보내거나, 장소를 바꾸거나(alt 에 이유를 남긴다), 예약 상태를 바꾼다. 검사를 통과할 때까지 반복한다.

### 4. 결과물 넷 만들기

```
python <스킬>/scripts/build_all.py <여행.yaml> <나갈 폴더>
```

검사에 오류가 있으면 만들지 않고 멈춘다. 따로 만들 때는 `build_infographic.py`, `build_webapp.py`, `build_kml.py`, `build_xlsx.py`.

### 5. 확인하고 건네기

- 인포그래픽 PNG 두 장을 열어 본다. 글자가 넘치거나 겹치면 데이터를 줄이거나(제목, 장소 이름) 사용자에게 알린다.
- 사용자에게 건넬 것과 쓰는 법:
  - 웹앱 `.html`: 폰으로 보내 파일로 열면 인터넷 없이 된다. 여행 날에는 그날 일정이 자동으로 펼쳐지고, 준비물 체크는 그 폰에 남는다.
  - 지도 `.kml`: 구글 내 지도(mymaps.google.com) > 새 지도 > 가져오기. 날짜마다 층이 하나씩 생긴다.
  - 시트 `.xlsx`: 구글 드라이브에 올리고 "구글 스프레드시트로 열기".
  - 인포그래픽: 폰 배경이나 단톡방에 한 장, 인쇄는 A4.
- 결과물은 데이터를 고친 뒤 다시 만든다. 결과물을 직접 고치면 다시 어긋난다.

## 지키는 것

- **사실은 한 번만.** 같은 값을 두 칸에 적지 않는다. 도착과 귀국은 하나씩.
- **지어내지 않는다.** 영업시간, 휴무, 나이 제한, 가격은 확인한 것만. 모르면 비우고 "확인 필요".
- **그림은 데이터로 그린다.** 인포그래픽에 AI 그림을 쓰지 않는다(AI 그림은 지도를 틀리게 그리고 글자에 오타를 낸다).
- **개인정보를 넣지 않는다.** 이름, 여권번호, 예약번호, 카드번호는 데이터 파일에도 결과물에도 넣지 않는다.
